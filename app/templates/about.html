Project Architecture & Implementation

1. Application Factory Pattern

The project uses Flask's recommended Application Factory pattern via create_app() in app/__init__.py. This decouples application configuration and allows multiple instances to be tested or deployed across development, testing, and production environments.

2. Modular Blueprints

Routes and business logic are segregated into modular blueprints:

  • main_bp (/, /about, /health): Handles front-end Jinja2 templated rendering.
  • api_bp (/api/users, /api/tasks): Provides RESTful JSON API endpoints for user and task entities.

3. SQLAlchemy ORM & Flask-Migrate

Database access is abstracted through Flask-SQLAlchemy with fully defined relational models (User and Task). Migrations are tracked and applied using Alembic through Flask-Migrate, allowing automated schema version control and zero-downtime upgrades.

4. Directory Layout

├── app/
│   ├── __init__.py      # Application factory & Blueprint registration
│   ├── extensions.py    # SQLAlchemy and Migrate instances
│   ├── models.py        # Relational models (User, Task)
│   ├── main/            # Main Blueprint (views)
│   ├── api/             # API Blueprint (REST endpoints)
│   ├── templates/       # HTML templates
│   └── static/          # Static assets (CSS/JS)
├── migrations/          # Flask-Migrate / Alembic version scripts
├── tests/               # Automated unit tests
├── config.py            # Environment configurations
├── run.py               # Main execution entry point
├── requirements.txt     # Python dependencies
└── .env.example         # Environment template
