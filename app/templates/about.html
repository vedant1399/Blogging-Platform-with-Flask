System Architecture & Technical Design

Full stack architecture documentation across Weeks 1 to 5

1. Commenting System & Relational Models (Week 5)

The commenting system enables interactive discussions on published blog posts:

  • Comment Model: Links to User (author) and Post (target article) with cascade deletion so removing a post cleans up all its discussion comments.
  • Flask-WTF CommentForm: Input validation (DataRequired, Length(2, 1000)) and CSRF token protection.
  • Granular Authorization: Adding comments is protected with @login_required. Comment deletion is permitted for either the comment author or the post owner (moderation).
  • Dynamic UI: Displays real-time comment counts, author avatars, timestamps, and contextual delete controls.

2. Modular Jinja2 Templating & Pagination (Week 4)

  • render_pagination Macro: Numbered page navigation with active indicators, disabled boundary buttons, and query preservation.
  • render_post_card Macro: Card layout rendering categories, tags, estimated reading time, comment count, and author.
  • Custom Template Filters: reading_time and format_datetime.
  • Public Author Profiles: Profiles at /users/<username> with paginated articles.

3. Blog Post CRUD & Taxonomy (Week 3)

  • Full CRUD lifecycle with author permission checks.
  • One-to-Many Category and Many-to-Many Tag relational modeling via the post_tags association table.
  • Flask-WTF forms and Quill.js rich text editor integration.

4. User Authentication & Sessions (Week 2)

  • User registration, login, logout, and persistent session management powered by Flask-Login.
  • Salted one-way password hashing using Werkzeug security.

5. Core Architecture & Migrations (Week 1)

  • Application Factory pattern (create_app()) with environment configurations.
  • Modular Blueprints (main_bp, auth_bp, posts_bp, api_bp).
  • Database schema migrations tracked via Alembic / Flask-Migrate in migrations/.
